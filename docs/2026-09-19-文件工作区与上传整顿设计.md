# 文件工作区与上传整顿设计

> 日期：2026-09-19
> 状态：已确认，待生成实现计划
> 范围：仅整顿到「本地 → 上传到服务器」。远程解压、部署自动化不在本次范围。

## 1. 背景与目标

右侧终端/文件面板与聊天附件存在以下问题：

- 聊天附件一律上传到后端临时目录，桌面端下 AI 与用户同机，这一传输无必要。
- 终端区拖放能力弱，文件列表操作稀少（缺新建文件夹、重命名、移动、上传文件夹、打包上传）。
- 后端整文件上传：`file.getBytes()` 全部读入内存，multipart 上限 200MB，无法支撑 GB 级部署包。
- 缺少「选择本地工作区 → 打包 → 上传」的完整链路。

目标：

1. 聊天附件在桌面端改为本地路径引用，AI 按需读本机磁盘，零上传。
2. 右侧终端/文件面板支持三种上传方式，底层统一为分片、断点续传引擎，内存恒定。
3. 整顿右侧面板操作体系，拖放语义清晰、不滑向编程智能体（不做本地文件树、本地 shell）。

### 参考调研结论

对 `E:\Agent的工作目录` 下 Claude Code、codex、opencode、pi、grok、pi-web 的调研：

- 本地 CLI 类 agent 没有「上传」概念，`@文件` 即本地路径，工具直接读写本地磁盘。
- pi-web（唯一 Web 形态）：服务端直接 fs 读写限定 roots（会话 cwd、项目根）；聊天框拖放仅收图片，base64 直入模型，不落盘。
- 共同规律：给 AI 看的文件不预先传输，要么直接读磁盘，要么 base64 进模型。

aye-aye 定位为「本地 AI ↔ 远程服务器」，文件天然两个去向：给 AI 看的走本地引用，给服务器的走真上传。

## 2. 总体设计：双轨制 + 三区域语义

| 轨道 | 去向 | 入口 |
|---|---|---|
| 上下文轨 | 引用本地路径，AI 按需读本机磁盘，零传输 | 聊天输入框 |
| 部署轨 | SFTP 真上传到远程服务器 | 右侧终端/文件面板 |

三个拖放区域：

1. **聊天输入框**
   - 本地文件 → 上下文附件（本地路径引用）。
   - 本地文件夹 → 弹小卡二选一：「作为上下文引用」/「上传到服务器」；选后者转入部署轨；选择在本次窗口内记住（可在小卡上改）。
   - 服务器文件树内部拖动 → 现有 `@path` 标签，不变。
2. **终端面板**：拖入 = 上传到终端当前工作目录。复用现有 `cd` 拦截的 cwd 跟踪（`getCwd()`）；浮层显示「松开上传到：/opt/app」；跟踪不到时回退家目录，浮层路径可手动修改。
3. **文件面板**：拖入 = 上传到文件树当前目录，浮层显示完整目标路径。

全局拖放浮层：黑白单色、细边框、T 形 logo 加载动画，遵循现有视觉契约。

## 3. 聊天附件链路（上下文轨）

### 桌面端

- Electron 35 已移除 `File.path`，preload 新增 `getPathForFile(file)`，内部使用官方 `webUtils.getPathForFile`。
- 附件 chip 仅保存：名称、大小、本地绝对路径；不再调用 `/api/agent/upload`。
- 发送时 `attachments: [{name, localPath}]` 写入 ChatRequest。

### AI 读取：唯一本地工具 read_local_file

- 工具分类 `READ`；调用时校验目标路径必须在本轮附件授权清单内（文件精确匹配，文件夹为其根目录之内）。
- 不提供本地目录浏览、本地 shell、本地写工具，边界清晰。
- 图片附件（< 10MB）直接转 base64 图片块进模型；其它类型由 AI 自行决定何时调工具读取。
- 文件夹作为上下文：先发受限文件清单（递归，跳过 node_modules/.git，上限 2000 项），AI 按需读其中文件。

### 浏览器模式降级

保留现有上传方式：文件进入后端 uploads 临时目录后，将路径注册进同一份附件授权清单。后端工具代码完全复用，对 AI 无差别。

### 历史会话

路径随消息持久化，重放仅显示文件名；AI 再读时若文件不存在，返回明确的「文件不可用」错误，不做自动读取。

## 4. 右侧面板整顿

### 终端 Tab

- 保留现有终端与「AI 执行」标记。
- 新增拖放区（复用 cwd 跟踪）。
- 手动上传成功后终端回显一行：`[上传] app.zip → /opt/app (128 MB)`，形成操作流水。

### 文件 Tab（ServerFileTree）

工具栏：

- 保留：刷新 / 上级 / 根目录 / 面包屑 / 排序 / 搜索。
- 上传改为分级按钮：上传文件 · 上传文件夹 · 选择本地工作区打包上传。
- 新增：新建文件夹（mkdir）。

右键菜单：

- 保留：打开/查看 · 下载 · 复制路径 · 删除。
- 新增：重命名、移动到…（路径选择输入，复用 SFTP rename）。

树内拖放：

Tab 头部样式统一为时间线控件规格（13px、无边框、hover 灰底）。

## 5. 分片上传引擎（方案 C：暂存校验 → 合并流直转 SFTP）

分片 5MB/片；前端最多 3 片并发；单片失败自动重试 3 次。

### 协议

```
1. POST /api/sftp/transfer/init
   {sessionId, remoteDir, name, size, totalChunks, uploadId, conflictStrategy}
   → {transferId, receivedChunks:[0,1,4], missingChunks:[2,3,5...]}

2. POST /api/sftp/transfer/chunk/{transferId}?index=n
   body: application/octet-stream（原始字节，流式落盘，不经 multipart）
   → {received:true, index:n}

3. POST /api/sftp/transfer/complete/{transferId}
   校验分片数量/大小 → 顺序打开分片文件拼成单个 InputStream
   → 只开一次 sftp.put() 流式写远程，SftpProgressMonitor 计量
   → 成功后删除本地分片目录
   冲突策略：error(默认) / overwrite / backup(覆盖前远程备份)

4. POST /api/sftp/transfer/abort/{transferId}   删除分片
   GET  /api/sftp/transfer/status/{transferId}  complete 在途时返回组装/转发进度
```

### 断点续传

- `uploadId` 由前端按文件路径 + 大小 + mtime 确定性生成，存 localStorage。
- 页面刷新、后端重启后重新 init：后端扫描 `{dataDir}/transfers/{uploadId}/` 下的 manifest.json 与分片文件，返回已收片序号，前端只传缺片。
- 分片带大小校验；complete 阶段 SFTP 写失败则分片保留，允许重试 complete，无需重传。

### 磁盘治理

- init 前检查可用磁盘空间（需 ≥ 文件大小 + 500MB 余量），不足直接报错。
- 后端启动时清扫分片目录：会话已失效的孤儿任务删除；有效任务保留 24 小时。
- 内存占用恒定（几十 KB 缓冲区），与包大小无关；2GB 包不 OOM。

## 6. 三种上传方式复用引擎

```
产物直传：     本地文件 ───────────────────────→ 分片引擎
压缩后上传：   选文件夹 → Electron 主进程归档 → 归档文件 → 分片引擎
整目录原样：   遍历目录 → 条目清单 → 批量建目录 → 每个文件独立跑分片引擎
```

- **压缩归档**：在 Electron 主进程执行（新增 archiver MIT 依赖，打包内置，无 CDN）；zip/tar.gz 可选；默认排除 node_modules/.git/.idea。归档开始前必须展示排除项清单供勾选确认（防止把本地运行态数据带到生产）；归档产物传完即删。
- **整目录上传**：File 对象的 `webkitRelativePath` 保留结构（拖入与选择均适用）；先批量 mkdir -p，再逐文件传，失败项汇总报告；检测到含 node_modules 且总体过大时，开始前提示改用压缩上传。
- **浏览器降级**：无本地归档能力，「打包上传」入口隐藏并提示使用桌面端；产物直传与整目录原样完整可用。

## 7. 上传任务管理器

右侧面板底部增加紧凑上传任务条：

- 每任务：文件类型图标 · 文件名 · 进度条 · 百分比/速度/剩余时间 · 暂停/继续/取消。
- 可展开为列表；最多 2 个任务并行，其余排队。
- 状态跨 Tab 切换保留（提升到 ConversationPage 或独立 store）。
- 全部完成后去抖刷新文件树（复用现有 400ms 机制）并在终端回显上传记录。
- 失败项提供「重试」；跨主机保护：主机切换后在途任务不串面板。

## 8. Electron IPC

preload 新增（最小授权面，不暴露任意 fs）：

| IPC | 作用 |
|---|---|
| `getPathForFile(file)` | File → 本机绝对路径（webUtils） |
| `selectWorkspace()` | 原生选目录对话框 |
| `selectFiles()` | 原生多选文件对话框 |
| `archiveWorkspace({dir, format, excludes})` | 主进程归档；`archive-progress` 事件推进度；返回归档路径与大小 |

浏览器模式：`<input multiple>` / `<input webkitdirectory>` / 拖放 FileList；无归档；附件走临时落盘。

## 9. 后端改动清单

新增：

- `TransferController` + `TransferService`：init/chunk/complete/abort/status；分片暂存与 manifest 持久化。
- `LocalFileReadTool`：受限本地读取；注册进 AgentBeansConfig 三处（Bean + 参数 + register）。
- `AttachmentRegistry`：会话级附件授权清单（本地路径与上传临时路径统一注册）。

修改：

- `SftpService`：新增 putStream(InputStream, monitor)、mkdir、rename。
- `SftpController`：新增 mkdir/rename 端点；下载改流式；旧整文件上传端点保留兼容。
- `ChatRequest` / `ChatService`：接收 localPath 附件并注册授权。
- 分片接口走 octet-stream 直读 `request.getInputStream()`，绕过 multipart 200MB 限制（multipart 配置保持不动）。

## 10. 错误处理与安全边界

- 网络抖动：单片重试 ×3；任务级失败分片保留可续。
- 大小不符：要求重传问题分片，不进入组装。
- SFTP 写失败、远程磁盘满：错误信息透传到任务条，complete 可重试。
- 归档/分片目录防路径穿越；本地工具严格白名单；SSH 会话失效则任务中止；高风险命令策略不受影响。

明确不做（本次边界）：

- 远程解压与部署自动化（后续独立设计）。
- 本地文件树、本地 shell/写工具。
- 批量多选操作。
- 浏览器端归档。
