# 无服务器流程测试报告

日期：2026-10-17

## 结论

无服务器条件下的接口流程与自动化回归通过：AI Core 226 项、Server 105 项，共 331 项测试，失败、错误、跳过均为 0。前端类型检查与生产构建通过，Electron 主进程、预加载和渲染构建通过。

这不是一次真实 Linux 服务器部署验收。浏览器控制持续超时，本轮也未完成 UI 逐步点击验证。

## 新增流程测试

`apps/aye-server/src/test/java/com/aye/server/chat/DeploymentHttpFlowTest.java` 新增 5 组集成测试，启动真实 Spring Boot 服务和随机回环端口，通过 HTTP 请求接口。模型由本地 SSE 服务按脚本响应；工作区、任务、审批、事件与部署阶段使用真实实现及独立 SQLite 数据库。

| 场景 | 验证结果 |
| --- | --- |
| 项目登记、目标登记、创建部署 | HTTP 成功，项目与任务关联、部署标记正确 |
| 正常部署流程 | 七个阶段记录完成；三次模拟修改操作均在审批通过后各执行一次 |
| 拒绝审批、重复提交旧审批 | 不执行工具；旧审批不可重放 |
| 等待审批时重复启动 | 返回 409，避免同一会话并发启动 |
| 停止与继续 | 停止后旧审批失效；再次停止返回无运行任务；续接保留原项目和服务器 |
| 构建失败与重试 | 工具错误和 failed 阶段可查询；重试后更新为 done，保留两轮记录 |
| 模型服务 503 | 任务以 error 结束；恢复后可创建下一轮 |
| 历史与刷新恢复 | 消息、会话和阶段可查询；事件游标不重复返回已读事件；SSE 返回 hello 与历史 snapshot |
| 数据持久化 | 新建数据库连接仍能读取部署目标；另有既有迁移与历史保留回归 |

## 模拟边界

- `run_local_async`、`deploy_upload`、`deploy_start_remote` 在新增集成测试中替换为不执行命令的工具。通过结果说明编排和审批链有效，不代表真实构建、传输和启动成功。
- `deploy_stage` 使用真实工具，因此验证了进度写入与查询；阶段成功由脚本模拟，不能代替服务器健康检查。
- 模型响应是确定性脚本，未使用付费模型，未验证真实模型对任意项目的识别和部署能力。
- 数据库、工作区、主机记录均为临时测试数据，测试结束关闭服务；未连接用户服务器、修改真实项目部署或更改权限设置。

```powershell
.\mvnw.cmd -B -ntp test '-DargLine=-Djava.io.tmpdir=E:\ideaCode\meCreate\aye-aye\apps\aye-server\target\analysis-test-tmp'
pnpm --dir apps/aye-frontend build

```

`java.io.tmpdir` 是当前 Windows 沙箱的临时目录配置，换目录运行时应调整为自己的可写路径。最终后端日志位于忽略目录 `.opensource/full-flow-final.log`。前端仍有既有的单包体积提示，不影响本次构建通过。
