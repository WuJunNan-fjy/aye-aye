# 小白一键部署实现计划

> **For agentic workers:** 按 Task 顺序实现，每 Task 结束跑测试并提交。步骤用 checkbox 跟踪。

**Goal:** 在对话中完成「选项目 → AI 看懂 → 准备环境 → 构建 → 确认产物 → 上传 → 远程启动验证」全流程。

**Architecture:** 复用现有 ChatService/AgentLoop 主循环，新增 `deploy` 包：工作区持久化、本机进程执行（同步 + 异步作业）、部署账本、部署专用工具集；阶段卡片由部署账本投影，前端轮询。

**Tech Stack:** Spring Boot、JSch（复用 SshSessionManager/SftpService/SshJobManager）、SQLite（Database）、JUnit5；React v2 + lucide。

设计文档：[docs/2026-09-20-小白一键部署设计.md](../2026-09-20-小白一键部署设计.md)

## 与设计文档的落地差异（实现时确认）

1. 会话绑定工作区：`ChatRequest` 增加可空字段 `workspaceId`；ChatService 在 turn 开始时绑定（WorkspaceStore 内存映射 sessionId→workspaceId），并把工作区路径注册进 LocalAttachmentRegistry。
2. 审批分级落在 ChatService 现有 `awaitConfirmEx` 回调内：
   - `run_local_async`：classifier DENY→自动拒、ALLOW→自动批、CONFIRM→正常弹卡；
   - 工具名白名单（`deploy_upload`、`deploy_extract_remote`、`deploy_start_remote`）：后端自行构造/严格校验命令与路径，回调自动批准；
   - 其余工具走既有引擎/卡片。
3. 远程操作不用自由文本 shell，改为三个窄工具：`deploy_extract_remote`、`deploy_start_remote`、`deploy_probe_remote`（无人工 E2E 也能跑通）。
4. `previous/` 回退编排第二刀再做；第一刀保留 console.log/run.pid。
5. 前端阶段卡轮询 `GET /api/deploy/runs/latest?sessionId=`（2s），不新增实时通道。

## 文件结构

后端新包 `com.termmind.server.deploy`：

| 文件 | 职责 |
|---|---|
| `WorkspaceStore.java` | workspaces CRUD + session 绑定（内存） |
| `WorkspaceController.java` | /api/workspaces REST |
| `LocalCommandClassifier.java` | 本机命令 ALLOW/CONFIRM/DENY |
| `LocalExecService.java` | 本机同步执行（cwd=工作区） |
| `LocalJobManager.java` | 本机异步作业（照搬 SshJobManager） |
| `RunLocalAsyncTool.java` / `LocalJobPollTool.java` | 本机异步工具 |
| `EditLocalFileTool.java` | 工作区内改文件 |
| `DeployStage.java` | 七阶段枚举 + 阶段状态 |
| `DeployRunStore.java` | deploy_runs 账本 CRUD |
| `DeployUploadTool.java` | 本地→流式 SFTP |
| `DeployStageTool.java` | 阶段推进 |
| `DeployExtractRemoteTool.java` / `DeployStartRemoteTool.java` / `DeployProbeRemoteTool.java` | 远程窄工具 |
| `DeployController.java` | 部署账本查询 |

修改：`storage/Database.java`（两表）、`chat/ChatRequest.java`（workspaceId）、`chat/ChatService.java`（绑定 + 审批分级）、`config/AgentBeansConfig.java`（装配 + 注册）。
